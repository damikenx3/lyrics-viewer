# 進階說明

給想在電腦上自己操作的人。需要 Node.js 20 以上，沒有其他依賴，不用 `npm install`。一般使用只要看 [README](../README.md) 就夠了。

## 資料夾

`library/` 是歌詞庫，也是編修歌詞的工作區，這個 repo 不追蹤它。歌詞和音源都放在這裡，一張專輯一個資料夾，一首歌一個 `.md`：

```
library/
  docs/lyrics-format.md         格式規格的副本
  星屑ノート/
    01 はじまりの歌.md            歌詞
    02 ひとりのうた.md
    cover.jpg                   封面
    001-はじまりの歌.flac         音源
```

`library/docs/lyrics-format.md` 是這個 repo 的 [`docs/lyrics-format.md`](lyrics-format.md) 的副本。改了規格要複製過去，兩份不同時 check 會警告。

build、check、serve 預設從 `library/` 讀歌詞，也從 `library/` 找音源，子資料夾怎麼分都可以。`dist/` 是 build 的輸出，這個 repo 同樣不追蹤。

`npm run share` 只打包已 commit 的歌詞，所以 `library/` 要是一個有 commit 的 git repo：

```
cd library
git init
git add .
git commit -m "星屑ノート：01 對時間"
```

音源檔很大又有版權，建議在 `library/.gitignore` 排除所有音檔格式（`*.flac`、`*.mp3`、`*.m4a`、`*.ogg`、`*.opus`、`*.wav`）。

## 手機上的補充

從檔案管理員開的頁面，瀏覽器不允許保持螢幕常亮，歌曲庫裡也不會出現螢幕常亮的開關。需要的話到系統設定把螢幕逾時調長。

build 時會把找得到的音檔寫成相對路徑提示，但手機上用相對路徑載入音檔一律會失敗。這些提示只在桌機直接開 HTML 或用 `serve` 時有用。

## 介面操作

介面幾乎只有圖示。桌機滑鼠停在圖示上，或手機長按圖示，會顯示文字說明。

**控制列**（由左到右）

- 清單＋音符：開啟歌曲庫（左上的封面縮圖也可以）
- ⏮ ⏭：上一首／下一首，依歌曲庫順序，可跨專輯
- ▶／⏸：播放／暫停；播放中按鈕會發光
- 螢光棒：打 CALL 標示，實心是開，空心是關

**進度條**

- 點或拖曳跳轉；拖曳時上方泡泡顯示目標時間與那裡的歌詞
- 短刻線是每段歌詞的開頭
- 時間左邊出現靜音喇叭：歌詞模式，沒有音訊，照時間軸播放

**歌詞**

- 目前唱到的行變亮並微微放大；call 以紫粉色標示，亮起時也會發光
- 點任一行，跳到那一行
- 手動捲動後會停止自動追蹤，下方出現箭頭圓鈕，點它回到目前位置

**標題區的圖示**

- 碼錶加斜線：歌詞還沒有時間標記（在 .md 行首加 `[分:秒.百分秒]`）
- 音符＋加號：連結這首歌的音檔，選一次就記住，下次開啟自動接上
- 行加叉：只有音訊、沒有歌詞；旁邊的檔案＋號可以加入 .md
- 三角驚嘆號：音檔無法播放，下面寫著原因和怎麼處理，音符＋加號可以改連結別的檔

**歌曲庫**

- 上方的專輯名稱：跳到那張專輯
- 檔案＋號：加入檔案，.md 與音檔可以一起選，手機上長按可多選。處理中會變成轉圈＋「已處理/總數」，這時再選的檔案會排隊處理
- 同一次選了同一首的多個音檔，只留音質最好的（FLAC、WAV ＞ M4A、Opus、Ogg ＞ MP3，同等級留檔案大的），其他算進警告
- 匯入的 .md 和內建歌詞庫有同一首歌時，以比較新的為準（內建的看 build 時間，匯入的看加入時間）
- 曲目右側：音符是已連結音訊，碼錶是有時間標記，碼錶加斜線是尚未對時
- 鉛筆：編輯模式，曲目右側換成移除按鈕
  - 音符＋減號：移除連結的音檔（連同存在瀏覽器裡的檔案）
  - 檔案＋減號：移除匯入的歌詞，改回內建版本；沒有內建版本的歌整首移除
  - 移除後下方提示的彎箭頭可以在 5 秒內復原，提示消失後才真的刪除
- A↓／A↑：調整歌詞大小
- 咖啡杯開關：播放時螢幕常亮。瀏覽器不允許時不會出現，例如從檔案管理員開啟、或用 serve 從區網的 http 網址開啟
- 文A：介面語言（中文／English／日本語）
- 往下拖、按 ✕ 或按返回鍵關閉
- 歌曲庫是空的時候，中間的檔案＋號可以直接加入檔案

**匯入結果**：一行一類，歌詞檔圖示或音檔圖示後面列出歌名（最多兩首，其餘以 +n 表示），警告圖示 n 是沒加入或略過的檔案數，原因另外列出

**返回鍵**

- 歌曲庫開著時只關歌曲庫
- 其他時候先出現「再按一次返回鍵離開」，約 2 秒內再按一次才離開頁面，誤按不會停掉音樂
- 剛開啟、還沒碰過畫面時，Chrome 不讓網頁攔截返回鍵，這時按返回會直接離開。點過任何地方之後就會有提示

**通知列與鎖定畫面**：上一首／下一首只在有音訊的歌之間移動；前後沒有可去的歌時，那個按鈕不顯示

**多個分頁**：從檔案 app 每開一次 Chrome 就多一個分頁。其中一個開始播放時，其他分頁會自動暫停

**鍵盤**：Space 播放／暫停；←/→ ±5 秒；Shift+←/→ 上／下一行；N／P 下／上一首；C 打 CALL；L 歌曲庫；Esc 關閉面板；焦點在進度條上時 PageUp／PageDown ±30 秒、Home／End 跳到開頭／結尾

## 新增一首歌

歌詞檔的寫法見 [lyrics-format.md](lyrics-format.md)。

1. 在 `library/` 的專輯資料夾裡新增 `曲序 歌名.md`。開頭複製同專輯其他檔的 front matter，接著寫 `# 曲序 歌名`，貼上歌詞，call 用括號包起來；歌詞本上沒有括號的 call 用 `{…}` 包起來，大括號不會顯示。
2. 音源放進同一個資料夾。用外部工具（例如字幕或 LRC 編輯器）取得每行的時間，直接寫到行首。工具輸出 LRC 的話，整行貼上就行。
3. `npm run check`，照著回報的「檔名:行號」修正。
4. `npm run build`。
5. 把 `dist/lyrics-viewer.html` 複製到手機，覆蓋舊檔。
6. 歌詞完成後到 `library/` 裡 commit，之後才能用 `npm run share` 輸出。

想邊聽邊對時間，可以開 `npm run serve`，改完 `.md` 重新整理頁面就會看到結果。

## 輸出 share 版

```
npm run share
```

把 `library/` 裡已經 commit 的歌詞打包成 `dist/share/lyrics-viewer.html`。歌詞有版權，這個檔案只限個人使用，不要提供給其他人。

- 只包含最後一次 commit 的內容。還沒 commit 的修改和新檔不會包含，指令會列出這些檔案；已經 commit 過的檔案用 commit 時的版本。
- 名為 `original` 的子資料夾（任何一層、不分大小寫）裡的歌詞檔會被略過，不管有沒有 commit，也不會列進警告。適合放原稿，不想讓它被打包進去。資料夾裡的圖片不受影響，仍可被別處的 `cover` 引用。`build`、`check`、`serve` 不套用這條規則。
- 不含音源，也不含音源的路徑提示，不會留下電腦上的檔名或資料夾。第一次在手機上播放時，用「加入檔案」選自己的音源。
- 封面會內嵌。
- 和 build 一樣先檢查，有錯誤就不輸出。

## 指令

| 指令 | 用途 |
|---|---|
| `npm run check` | 解析並檢查歌詞庫，不輸出檔案 |
| `npm run build` | 檢查後輸出 `dist/lyrics-viewer.html`，有錯誤就不輸出 |
| `npm run serve` | 區網伺服器，見「在區網用 serve」 |
| `npm run share` | 只打包已 commit 的歌詞，輸出 `dist/share/lyrics-viewer.html`，見「輸出 share 版」 |
| `npm test` | 跑測試 |

選項接在 `--` 後面，例如 `npm run build -- --audio-dir "D:\MyMusic\星屑ノート"`。

| 選項 | 預設 | 用在 |
|---|---|---|
| `--library <資料夾>` | `library` | 全部 |
| `--audio-dir <資料夾>` | 跟 `--library` 相同 | build、check、serve。會往下找所有子資料夾的音檔 |
| `--out <檔案>` | build：`dist/lyrics-viewer.html`；share：`dist/share/lyrics-viewer.html` | build、share |
| `--port <埠號>` | `8080` | serve |

check 和 build 會列出每首歌「有時間的行數/總行數」、每首歌對到的音檔，然後是問題清單，每一筆都是 `檔名:行號: 等級：說明`：

- 錯誤：時間格式不對（例如 `[0:5.2]`、秒數 60 以上、小數只有一位、全形的數字或括號、範圍用 `~` 或 `〜`、少了 `]`）、結束時間不晚於開始時間、註解或 front matter 沒有結束、一個檔裡有第二個 `#` 標題、同專輯有同名的歌。有錯誤時 build 不輸出檔案，指令以非零結束。
- 警告：開始時間比前一行早、重複的行首時間、括號沒關或多了 `)`、行首時間寫在行中間、行尾的 `<mm:ss.xx>`、行內時間早於行的開始或晚於行的結束、front matter 重複的 key、`#` 標題之前的文字、LRC 的 `[offset:]`、封面太大或找不到。
- 提示：有時間軸的歌裡還沒有時間的行、LRC 的標籤行。

## 在區網用 serve

```
npm run serve
```

音源放在 `library/` 以外的地方時，用 `--audio-dir` 指定，例如 `npm run serve -- --audio-dir "D:\MyMusic\星屑ノート"`。

啟動後會印出本機和區網網址，例如 `http://192.168.1.23:8080/`。手機和電腦連同一個 Wi-Fi，用手機的 Chrome 開那個網址。Windows 第一次會跳防火牆詢問，允許「私人網路」即可。

- 每次開啟 `/` 都重新讀歌詞庫並打包，改完 `.md` 重新整理就好，不用重跑 build。
- 音檔從電腦串流，支援拖曳進度，手機不用先存音檔。
- `/src/index.html` 是不打包的開發版，模組直接由瀏覽器載入，同樣會帶入目前的歌詞庫。
