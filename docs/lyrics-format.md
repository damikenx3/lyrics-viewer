# 歌詞檔格式規格

lyrics-viewer 的歌詞檔是一首歌一個 `.md` 檔，歌詞和時間軸寫在一起。照這份規格寫的檔案就能正常使用。

副檔名是 `.md`，但這不是 Markdown。只有這份規格列出的寫法有特別意義，其他像 `**粗體**`、`- 清單`、`## 小標題` 都會照字面當成歌詞顯示。

規格裡的「錯誤」代表檔案寫錯了，必須修正才能使用。「警告」代表檔案可以使用，但結果可能和你預期的不同。

## 1. 檔案

- 一首歌一個檔，副檔名 `.md`，不分大小寫。
- 編碼 UTF-8，開頭有沒有 BOM 都可以。換行用 LF、CRLF、CR 都可以。
- 檔名建議寫成 `曲序 歌名.md`，例如 `01 はじまりの歌.md`。檔名只是方便找，歌名和曲序以檔案裡的 `#` 標題為準。
- 一張專輯的檔放在同一個資料夾。封面圖和音源可以放在同一個資料夾。
- 每行行尾的空白和 tab 一律忽略。

## 2. 整體結構

```md
---
album: 星屑ノート
artist: 架空シンガー
cover: cover.jpg
audio: 01-hajimari.flac
---

# 01 はじまりの歌

作詞：誰か / 作曲：誰か

[00:12.50] 窓をあけて
[00:15.80] 朝の光をあつめて
[00:19.20-00:23.00] 夜空《よぞら》に (ハイ！)

[00:30.00] みんなで<00:32.40>(せーの！)
[00:36.00]
```

由上到下依序是：

1. front matter，這首歌的設定。選填。
2. `#` 標題，寫曲序和歌名。
3. 歌詞，直到檔案結尾。

最簡單的檔案只要標題和歌詞：

```md
# はじまりの歌
窓をあけて
```

## 3. front matter

檔案第一行是 `---` 時，到下一個 `---` 或 `...` 為止是 front matter。這首歌的設定都寫在這裡。

- 一行一組 `key: value`。key 以英文字母開頭，不分大小寫。
- 空行和以 `#` 開頭的行略過。
- 值可以用 `"…"` 包起來，裡面用 `\` 跳脫；或用 `'…'` 包起來，`''` 代表一個 `'`。沒有引號時，空白後面的 `#` 起算是註解。

| key | 作用 |
|---|---|
| `album` | 專輯名稱。沒寫時見第 6 節 |
| `artist` | 歌手 |
| `year` | 發行年份 |
| `cover` | 專輯封面圖檔，路徑相對於這個 `.md`。支援 jpg、jpeg、png、webp、gif |
| `audio` | 這首歌的音源檔名，見下面的「什麼時候要寫 audio」 |
| `offset` | 秒數，套用到這首歌的所有時間。正值整首延後，負值整首提早，加完小於 0 的時間當成 0 |

- 同一張專輯的每個檔都寫一樣的 `album`、`artist`、`cover`。
- 封面找不到、格式不支援、超過 400 KB 都是警告。建議用 800px 以內的 JPEG。
- 同一個 key 寫兩次是警告，以後面的為準。
- `offset` 不是數字是警告，這個設定會被忽略。
- 不是 `key: value` 形式的行是警告，這行會被略過。
- 其他 key 沒有作用，也不會警告。
- 找不到結尾的 `---` 是錯誤。

### 什麼時候要寫 audio

沒寫 `audio` 時，音源會依序用這兩種方式自動配對到歌：

1. 音源檔標籤裡的歌名。有好幾首同名的歌時，再看標籤的專輯和曲序。
2. 音源檔名裡含有歌名。

比對時忽略大小寫、全形半形、空白和標點。所以音源有正確的標籤，或檔名裡有歌名，就不用寫 `audio`。

下面這些情況不會自動配對，要寫 `audio`：

- 標籤的歌名相同，但標籤的專輯和曲序都和這首歌不同。
- 檔名開頭有曲序數字，但和這首歌的曲序不同。
- 檔名比對時，英數歌名沒有對在字詞邊界上，例如歌名「Ai」不會配到「Rain.flac」。其他歌名去掉空白和標點後少於 3 個字時，也不用檔名比對。
- 檔名或標籤有 instrumental、off vocal、inst、karaoke、カラオケ、オフボーカル、インスト，但歌名沒有。

`audio` 寫音源的檔名，路徑部分會被忽略，不分大小寫。只有副檔名不同也算同一個檔，寫 `01.flac` 也會配到轉檔後的 `01.mp3`。

## 4. 歌曲標題

以 `#` 開頭的行是歌曲標題，寫曲序和歌名。一個檔只能有一個標題。

- `#` 後面的空白可以省略，也可以用全形空白。`#02 歌名`、`#　歌名` 都算標題。
- `##` 以上不算標題，會當成歌詞。
- 出現第二個以 `#` 開頭的行是錯誤。以 `#` 開頭的歌詞要寫成 `\#`。
- 標題開頭的數字是曲序，數字後面要接 `.`、`-` 或空白，再接歌名。歌名本身以數字開頭、又不是曲序時，在前面加 `\`。

| 標題 | 曲序 | 歌名 |
|---|---|---|
| `# 01 歌名` | 1 | 歌名 |
| `# 01. 歌名`、`# 3-歌名`、`# 3 - 歌名` | 1、3、3 | 歌名 |
| `# 2024` | 無 | 2024 |
| `# \7 days` | 無 | 7 days |
| `# 歌名` | 無 | 歌名 |

- 同一張專輯的歌依曲序排列。
- 標題裡的括號不是 call。
- 標題行可以寫註解，註解不會出現在歌名裡。
- 標題之前有文字是警告，那些文字會被忽略。
- 沒有 `#` 標題時，歌名和曲序取自檔名，規則相同。`07 曲名.md` 是第 7 首「曲名」。

### 同一首歌的判斷

「專輯名稱＋歌名」相同就是同一首歌。比較前會做 NFKC 正規化、轉小寫，並去掉空白、標點和符號，所以「ほし・ストーリー」和「ほしストーリー」是同一首，「PON-PON!!!」和「pon pon」也是。

同一張專輯有兩個檔是同一首歌是錯誤。

## 5. 註解

`<!-- … -->` 是備註，不顯示，可以跨行，可以寫在歌詞行中間。註解裡寫什麼都不會被當成設定。

- 只有註解的行不算空行，不會多出段落間距。
- `<!--` 沒有對應的 `-->` 是錯誤。

## 6. 專輯

專輯名稱依序取用：

1. front matter 的 `album`
2. 檔案所在資料夾的名稱。檔案直接放在歌詞庫最上層、不在任何資料夾裡時沒有這一項
3. 「未分類」

建議每個檔都寫 `album`，不要依賴資料夾名稱。

## 7. credits

標題之後、第一行歌詞之前，符合下列條件的行是 credits，和歌詞分開顯示在歌名下方，一行一筆。

- 含 `Lyrics by`、`Words by`、`Music by`、`Composed by`、`Arranged by`、`Written by`，不分大小寫
- 含 `作詞`、`作曲`、`編曲`
- 以 `詞：` 或 `曲：` 開頭，冒號半形全形都可以

這些行不能有時間標記。中間夾著空行或註解不影響。出現第一行不符合條件的文字之後，credits 就結束了，後面再出現 `作曲` 之類的行都是歌詞。

## 8. 歌詞行與空行

credits 之外的每一行都是歌詞行，照原樣顯示，換行位置和檔案相同。

- 沒有行首時間的行，行首的空白會保留。有行首時間時，時間標記前後的空白只是分隔，不會顯示。
- 每個空行都是一個段落間距，連續兩個空行就是兩倍間距。歌曲開頭和結尾的空行會去掉。
- 只有註解的行、只有時間標記的行都不算空行。
- 空行隔開的一組行叫做「段」。call 的括號配對以段為範圍。
- 整首歌沒有任何歌詞是警告。

## 9. 時間標記

### 9.1 時間的寫法

| 寫法 | 例子 | 說明 |
|---|---|---|
| `mm:ss` | `03:05` | |
| `mm:ss.xx` | `03:05.20` | 小數 2 位 |
| `mm:ss.xxx` | `03:05.205` | 小數 3 位 |
| `mm:ss:xx` | `03:05:20` | 部分 LRC 工具的寫法，等同 `03:05.20` |

- 分鐘 1 到 4 位數，可以超過 59，`[75:00.00]` 是 75 分鐘。
- 秒數一定寫 2 位數，而且小於 60。
- 時間精確到毫秒。
- 方括號內側和範圍的 `-` 兩邊可以有空白，`[ 00:12.50 ]`、`[00:01.00 - 00:02.00]` 都可以。

下面這些都是錯誤。寫錯的標記不會顯示成歌詞。

| 寫法 | 問題 |
|---|---|
| `[0:5.2]` | 秒數要 2 位數 |
| `[00:75.00]` | 秒數要小於 60 |
| `[00:05.2]` | 小數要 2 或 3 位 |
| `[00:05.2345]` | 小數超過 3 位 |
| `［００：０５．２０］` | 全形字元 |
| `[00:01.00~00:02.00]` | 範圍要用半形 `-`，`〜`、`–`、`—` 也不行 |
| `[00:05.20` | 少了 `]` |
| `[00;05.20]` | 分隔要用冒號 |

### 9.2 行首時間

寫在行的最前面，前面只能有空白或註解。

| 寫法 | 意思 |
|---|---|
| `[00:12.50] 歌詞` | 這行在 00:12.50 亮起 |
| `[00:12.50-00:16.00] 歌詞` | 這行在 00:12.50 亮起，00:16.00 熄滅 |
| `[00:12.50][01:40.00] 歌詞` | 這行在兩個時間都會亮，和 LRC 的重複行相同。標記之間可以有空白 |

- 範圍的結束時間不晚於開始時間是錯誤。
- 同一行寫了兩個完全相同的時間是警告，多的那個會被略過。
- 行中間出現像時間的 `[00:12.50]` 是警告，它會照字面顯示。行中間要標時間請用第 9.5 節的行內時間。
- 開始時間比前一行早是警告。同一行有多個開始時間時，這行不列入比較，因為 LRC 的重複行本來就不照順序。

### 9.3 什麼時候熄滅

1. 寫了範圍的行，在結束時間熄滅。
2. 沒寫結束時間的行，亮到下一個時間點。時間點是這首歌所有行的開始時間，加上第 9.4 節的結束標記，取比這行開始時間晚的第一個。
3. 後面沒有任何時間點時，亮 5 秒。

別的行用範圍寫的結束時間不算時間點，只屬於那一行。這樣一行跨很久的 call 不會讓主歌詞提早熄滅。

時間重疊的行會同時亮。例如：

```md
[00:01.00-00:09.00] (ずっと続くコール)
[00:02.00] 一行目
[00:04.00] 二行目
```

第一行亮 1 到 9 秒；`一行目` 亮 2 到 4 秒；`二行目` 從 4 秒開始，後面沒有時間點，亮到 9 秒。2 到 9 秒之間同時有兩行亮著。

歌曲長度是所有行最晚的熄滅時間。沒有音源、只有歌詞時，就照這個長度播放。

### 9.4 結束標記

只有時間標記、沒有文字的行是結束標記，例如 `[00:36.00]`。

- 這行不顯示，也不算空行。
- 它的時間會變成一個時間點，讓前面沒寫結束時間的行在這時熄滅。最常用在最後一行，或間奏開始的地方。
- 只寫 `<00:36.00>` 也一樣。
- 結束標記寫成範圍是警告，結束時間會被忽略。

### 9.5 行內時間

在行中間寫 `<mm:ss.xx>`，標記後面的文字到這個時間才亮，亮了以後維持到這行熄滅。

```md
[00:30.00] みんなで<00:32.40>(せーの！)
```

`みんなで` 在 30 秒和這行一起亮，`(せーの！)` 到 32.40 秒才亮。

- 標記的效果一直延續到下一個 `<mm:ss.xx>`。中間被 call 或振假名切開也一樣。
- 同一個位置有好幾個行內時間時，用最後一個。
- 一行只有行內時間、沒有行首時間時，第一個行內時間就是這行的開始時間。
- 有多個行首時間的行，行內時間以第一個行首時間為準，每次重複都平移同樣的量。`[00:10.00][01:10.00] あ<00:11.00>い` 的 `い` 第一次在 00:11 亮，第二次在 01:11 亮。
- 這些情況是警告：行內時間後面沒有文字、行內時間早於這行的開始、行內時間不早於這行的結束。最後一種情況下，標記後面的文字永遠不會亮。
- 行內時間的格式寫錯和行首時間一樣是錯誤。

### 9.6 有沒有時間軸

- 任何一行有時間，這首歌就有時間軸。有時間軸的歌裡沒有時間的行照常顯示，但永遠不會亮。
- 整首都沒有時間的歌照樣顯示，只是不會亮。適合先放歌詞、之後再對時間。

## 10. 打 CALL

`(…)` 或全形 `（…）` 括起來的文字是 call，括號本身也算 call，一起用另一個顏色顯示。只看括號，不看內容。

- 可以跨行。開括號和關括號在不同行時，中間的每一行都算。
- 不能跨段，也就是不能跨空行。括號到段落結尾還沒關是警告，這個開括號和後面的文字都當成一般文字。
- 前面沒有對應開括號的 `)` 是警告，它會當成一般文字。
- 半形全形可以混著配對，`(…）` 也算一對。
- 括號裡面又有括號時，以最外層為準，整段都是 call。
- 括號本身是歌詞時寫成 `\(`、`\)`、`\（`、`\）`。
- 標題和 credits 裡的括號不算。

把讀音或補充說明寫在括號裡，例如 `桃 (源) 郷`，也會被當成 call。讀音請改用第 11 節的振假名，或把括號跳脫。

## 11. 振假名

用青空文庫的寫法，讀音顯示在文字上方。

| 寫法 | 加讀音的文字 |
|---|---|
| `夜空《よぞら》` | `《` 前面連續的漢字，包含 `々`、`〆`、`ヶ` |
| `｜お住まい《ドメイン》` | `｜` 和 `《` 之間的文字，可以是假名、英文或混合 |
| `\|お住まい《ドメイン》` | 半形 `\|` 效果相同 |

- 讀音和文字必須在同一行。
- 沒有 `｜` 時，往前找漢字只找到上一個振假名結束的地方為止。
- 有 `｜` 時，從 `《` 往前找同一行最近的 `｜` 或 `|`，同樣只找到上一個振假名為止。歌詞本身含有 `|` 又在同一行用了振假名時，那個 `|` 要寫成 `\|`。
- 可以寫在 call 裡面，會跟著 call 變色。一組振假名不會被切開，整組沿用第一個字的 call 屬性。
- 文字或讀音中間的行內時間會移到這組振假名的前面。

這些情況是警告，會照字面顯示：

- `《》` 裡沒有讀音。
- `《` 前面不是漢字，也沒有用 `｜` 標出起點。例如 `あいう《x》`。
- `《` 沒有對應的 `》`。這時這一行後面的振假名都不處理。

單獨出現的 `》` 照字面顯示，不會警告。

## 12. 跳脫

反斜線 `\` 後面接下列字元時，顯示那個字元本身，沒有特別意義：

`(`　`)`　`（`　`）`　`《`　`》`　`｜`　`|`　`[`　`]`　`<`　`>`　`#`　`\`

| 想顯示 | 寫成 |
|---|---|
| 不是 call 的括號 | `\(笑\)` |
| 以 `#` 開頭的歌詞 | `\#hashtag` |
| 行首的 `[00:00]` 字樣 | `\[00:00]` |
| `<00:12.00>` 字樣 | `\<00:12.00>` |
| 反斜線本身 | `\\` |

反斜線後面接其他字元時，反斜線照字面顯示。

## 13. 和 LRC 的相容性

- LRC 的時間行可以整行貼上，`[mm:ss.xx]` 和重複行 `[t1][t2]` 都相同。
- enhanced LRC 的逐字時間 `<mm:ss.xx>` 就是第 9.5 節的行內時間。
- 整行是 LRC 標籤的行不顯示：`[ti:]`、`[ar:]`、`[al:]`、`[au:]`、`[by:]`、`[length:]`、`[re:]`、`[ve:]`、`[#:]`。歌名請寫在 `#` 標題，歌手和專輯請寫在 front matter。
- `[offset:]` 不支援，寫了是警告並被忽略。LRC 的 offset 單位是毫秒，正值代表提早；這裡的 `offset` 單位是秒，正值代表延後。`[offset:+500]` 要改成 front matter 的 `offset: -0.5`。

## 14. 錯誤與警告一覽

### 錯誤

- 時間格式寫錯，各種情況見第 9.1 節
- 範圍的結束時間不晚於開始時間
- front matter 沒有結尾的 `---`
- 註解 `<!--` 沒有對應的 `-->`
- 一個檔裡有第二個 `#` 標題
- 同一張專輯有兩個檔是同一首歌

### 警告

- front matter 有不是 `key: value` 的行
- front matter 同一個 key 寫了兩次
- `offset` 不是數字
- 封面找不到、格式不支援、超過 400 KB
- `#` 標題之前有文字
- 整首歌沒有任何歌詞
- 開始時間比前一行早
- 同一行重複的行首時間
- 結束標記寫成範圍
- 像時間的 `[…]` 寫在行中間
- 行內時間後面沒有文字、早於行的開始、不早於行的結束
- 括號沒有關，或多了關括號
- 振假名沒有讀音、找不到要加讀音的文字、`《` 沒有關
- LRC 的 `[offset:]`
